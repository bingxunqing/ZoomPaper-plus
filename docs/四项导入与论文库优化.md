# 导入与论文库优化

名称与发布版本保持 ZoomPaper Plus 0.4.2。数据库内部结构升级到 19，扩展通信协议升级到 2；旧扩展仍可通过原有深链接导入。

## 已实现

| 范围 | 实现 | 验证 |
|---|---|---|
| 论文列表 | 后端每页最多 500 条，界面每次取 200 条；SQLite 变更记录驱动增量刷新；先选定一页 ID 再聚合文件夹和阅读时间；列表与网格只挂载可见范围 | 万条数据的可见行数量测试、分页中途变更重试、删除与局部修改合并 |
| 元数据 | 浏览器标题、作者、摘要、会议、DOI/arXiv 标识在全文解析前入库；DOI/arXiv 查询独立后台执行；记录字段来源，保护手动重命名与原文未变的中文缓存 | 来源优先级、中文缓存、会议保留、arXiv 版本标识匹配 |
| 网站适配 | ACL、arXiv、OpenReview、CVF、会议论文集五组规则拆成模块；统一注册与优先级；继续保留通用引用标签、JSON-LD 和链接识别；多论文页面不冒用其他条目的 JSON-LD | 五组精简 HTML 结构样本、路由测试、未知网站与歧义页面 |
| 扩展通信 | 能力握手；元数据通过有大小/目录/请求 ID 校验的 JSON 文件传递；任务存入 storage.local；重启恢复；回执区分已保存和后台处理；本地 HTTP 服务限制同时连接数 | 单元测试、真实 Chrome MV3 下载/回执/浏览器重启恢复 |

查询论文时不再读取 Markdown 或 publication.json。旧库的会议信息和 GitHub 地址一次性在后台回填，完成后主动刷新界面。变更记录保留约两万条，过旧的客户端缓存会重新分页加载。快速拖选会补齐跳过的行，并在滚动区域边缘继续滚动。

## 使用与边界

- Chrome 重新加载原来的 `ZoomPaper-Plus-Connector` 文件夹即可更新扩展，无需创建第二个扩展。
- 下载和正文解析是两件事：已保存即可整理论文；正文解析失败不会撤销已保存的网页元数据。
- DOI/arXiv 查询需要网络，失败可从后台任务重试，不影响论文入库。
- 首次加载仍会分页构建全库的本地缓存，筛选与排序保留原有界面行为；后续刷新只取变更。尚未改为服务端筛选，也没有宣称具体倍数的性能提升。
- 网站样本是精简结构回归样本，不代表所有网站登录、验证码和反爬场景均通过。
- MV3 测试使用实际 Chromium service worker、下载 API、storage.local 和 HTTP 请求；App 回执服务及深链接接收端由隔离测试桩替代。未对用户的生产论文库进行重启或迁移测试。

## 验证命令

```sh
npm test
cargo test --manifest-path src-tauri/Cargo.toml --lib
npm run build
npm run package:extension
# 安装 Playwright 后运行独立浏览器测试；不使用日常 Chrome 配置。
node tests/mv3/import-session.cjs
```

若 Playwright 位于其他依赖目录，可以设置 `ZOOMPAPER_PLAYWRIGHT_ROOT` 为该 node_modules 目录。测试所需浏览器安装命令为 `playwright install chromium --no-shell`。
