## 本轮发现并修复的高影响问题

- 首次 embedding 模型准备在持有全局数据库锁时进行，导致文件夹创建等功能一起卡住。现在模型与文件处理在锁外完成，数据库锁只覆盖查询或写入。
- 第一条问答生成后，服务端会话 ID 更新会重新挂载聊天框，导致“快速/深度”状态重置和下一条草稿丢失。现在只有用户主动新建或切换会话时才重置。
- SSE 已输出正文后仍可能等待连接关闭，停止按钮也只有收到下一块网络数据才生效。现在识别协议结束标记、空闲时轮询取消，并有 120 秒无响应上限。
- DeepSeek 思考模式与工具调用要求回传历史 `reasoning_content`，旧会话无法满足。DeepSeek 工具请求显式使用可重放的非思考模式；应用自己的检索轨迹、引用和计时保持不变。
- 批注的异步全量保存可能由旧请求覆盖新请求，卸载前的最后一次 PDF 编辑也可能丢失。现在按论文和类型串行保存，PDF 改为立即排队写入。
- 损坏或读失败的批注文件过去会被当作空数组，下一次保存可能覆盖原文件。现在显示错误并停止自动保存。
- 博客审稿提示可能自行补数据再质疑来源。现在明确论文内容是不可信输入，数字和引述必须能在原文定位。

## 仍有边界

- 关键词搜索来自解析后的 Markdown 段落，当前没有可靠页码时只能打开论文并恢复阅读位置。
- 首次下载 embedding 模型仍依赖网络；本轮修复保证下载不会持有数据库锁，但无法消除网络本身的失败。
- 没有执行永久删除论文，避免把“测试所有功能”变成不可恢复的数据操作；删除确认与后端数据清理由现有测试覆盖。
- 本轮参考 Zotero 的集合、快速搜索、阅读状态、快捷键与笔记导出思路，并未宣称达到 Zotero 的全部功能范围。
